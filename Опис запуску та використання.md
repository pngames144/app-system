# Опис запуску та використання

Документ описує додані функції для Flutter + PocketBase застосунку: щоденні рутини, серії виконання, магазин, покупки, покарання та перепустки на амністію.

## 1. Запуск

### PocketBase

У PowerShell з кореня проєкту:

```powershell
.\pocketbase\pocketbase.exe serve --dir .\pocketbase\pb_data --migrationsDir .\pocketbase\pb_migrations --hooksDir .\pocketbase\pb_hooks
```

Адмін-панель: `http://127.0.0.1:8090/_/`

API: `http://127.0.0.1:8090/api/`

Міграції виконуються автоматично під час запуску. Їх також можна перевірити окремо:

```powershell
.\pocketbase\pocketbase.exe migrate up --dir .\pocketbase\pb_data --migrationsDir .\pocketbase\pb_migrations --hooksDir .\pocketbase\pb_hooks
```

### Flutter

```powershell
flutter pub get
flutter analyze
flutter test
flutter run
```

Для Android-емулятора клієнт уже використовує `http://10.0.2.2:8090`. Для Windows, iOS або фізичного телефона змініть `AuthService.baseUrl` на адресу, доступну з потрібного пристрою.

### Локальний тестовий акаунт

Для перевірки локальної бази створено окремий тестовий профіль:

```text
Email:    test.user@app-system.local
Password: TestPassword123!
User ID:  5tnw8om7ni1orh2
```

Ці реквізити призначені тільки для локального `127.0.0.1:8090` і не повинні використовуватися в production. Токен навмисно не збережений: отримуйте його новим запитом `auth-with-password` перед тестуванням.

Локальний superuser для керування тестовими товарами:

```text
Email:    test.admin@app-system.local
Password: TestAdminPassword123!
```

Це також тестові локальні реквізити. Після завершення перевірок їх можна видалити командою `pocketbase superuser delete`.

## 2. Нові колекції PocketBase

### `routines`

Поля:

- `user` — relation до користувача;
- `title`, `description` — назва та опис;
- `expReward` — нагорода;
- `streak` — кількість послідовних днів;
- `status` — `Pending`, `Completed` або `Failed`;
- `dueDate` — дата, до якої треба виконати поточний цикл;
- `lastCompletedDate` — остання дата виконання.

Правила доступу обмежують записи власником. У `lib/services/routine_service.dart` доступні `fetchRoutines`, `createRoutine` та `completeRoutine`.

`completeRoutine`:

1. перевіряє, що рутина належить поточному користувачу;
2. не дозволяє виконати її двічі в один день;
3. додає `+1` до `streak`, якщо попереднє виконання було вчора;
4. починає нову серію з `1`, якщо день було пропущено;
5. переносить `dueDate` на наступний день.

### Scheduled-перевірка

Файл `pocketbase/pb_hooks/routines.pb.js` реєструє cron `59 23 * * *`. Він знаходить невиконані рутини, для яких `dueDate <= @now`, і встановлює:

```json
{
  "status": "Failed",
  "streak": 0
}
```

Перевірка виконується за часовою зоною сервера PocketBase. Для передбачуваної поведінки встановіть серверу потрібну часову зону або використовуйте UTC.

### `shop`

Публічна для читання колекція товарів із полями `name`, `price`, `category`, `item`. Через API її зміну закрито.

### `purchases`

Журнал покупок із полями `user`, `item`, `price` і системними датами. Користувач бачить лише власні покупки.

### `punishments`

Поля:

- `user` — власник;
- `routine` — обов'язкове relation до конкретної рутини;
- `type`, `description`, `value` — конфігурація покарання;
- `status` — поточний статус покарання, початково `Pending`; факт амністії зберігається окремою подією.

`updateRule` і `deleteRule` заблоковані. Тому після створення покарання його не можна змінити або видалити через REST API, зокрема в день створення. Покарання створюється параметром `punishment` у `RoutineService.createRoutine`.

### `event_logs`

Незмінний журнал подій. Для амністії запис містить `eventType = amnesty_pass_used`, користувача, покарання та опис дії.

### Поля профілю користувача

- `amnestyPasses` — залишок перепусток, від `0` до `2`;
- `amnestyWeekStart` — початок поточного UTC-тижня.

Сервіс автоматично вважає залишок рівним `2`, якщо почався новий тиждень, і після використання зменшує його на один.

## 3. Flutter API

### Рутини

```dart
final routine = await routineService.createRoutine(
  RoutineModel(
    id: '',
    title: 'Ранкова зарядка',
    dueDate: DateTime.now().toUtc(),
    expReward: 10,
  ),
  punishment: const PunishmentDraft(
    type: 'hp',
    description: 'Зменшити HP на 5',
    value: 5,
  ),
);

await routineService.completeRoutine(routine.id);
```

### Магазин

```dart
final items = await shopService.fetchItems();
final receipt = await shopService.purchaseItem(itemId, userId);
```

`purchaseItem` спочатку читає товар і баланс, потім перевіряє `coins >= price`. Якщо монет недостатньо, викидається `StateError` і баланс не змінюється. Після списання створюється запис у `purchases`; якщо створення receipt не вдається, сервіс відновлює попередній баланс.

Важливо: поточна реалізація захищає сценарій покупки на рівні Flutter-сервісу, але старе правило `users.updateRule = id = @request.auth.id` дозволяє авторизованому клієнту напряму змінити власні `coins` через REST. Для production потрібна окрема серверна wallet-модель або перевірений custom endpoint, який не змінює auth-запис під час активної сесії.

### Амністія

```dart
await punishmentService.useAmnestyPass(punishmentId, userId);
```

Метод перевіряє власника, статус покарання та ліміт тижня, після чого послідовно зменшує `amnestyPasses` і створює подію в `event_logs`. Сам запис покарання не змінюється, бо його редагування заблоковане; факт амністії визначається подією `amnesty_pass_used`. Якщо створення події не вдається, pass відновлюється.

## 4. Перевірка через Postman

У всіх захищених запитах додайте заголовок:

```text
Authorization: Bearer <token>
Content-Type: application/json
```

Токен повертається запитом:

```http
POST http://127.0.0.1:8090/api/collections/users/auth-with-password
Content-Type: application/json

{
  "identity": "user@example.com",
  "password": "password123"
}
```

### Перевірка рутини

```http
GET http://127.0.0.1:8090/api/collections/routines/records
```

Створення:

```http
POST http://127.0.0.1:8090/api/collections/routines/records
Content-Type: application/json

{
  "title": "Вода",
  "description": "Випити склянку води",
  "expReward": 5,
  "streak": 0,
  "status": "Pending",
  "dueDate": "2026-09-30 23:59:00.000Z"
}
```

Для ручної перевірки структури можна виконати `PATCH /api/collections/routines/records/<routineId>` з:

```json
{
  "status": "Completed",
  "streak": 1,
  "lastCompletedDate": "2026-09-30 12:00:00.000Z"
}
```

У застосунку використовуйте `completeRoutine`, бо він обчислює streak і наступний `dueDate` централізовано.

Не використовуйте цей PATCH як основний production-сценарій: він дозволяє вручну передати `streak`. Коректний сценарій виконання проходить через `RoutineService.completeRoutine`.

### Перевірка магазину

```http
GET http://127.0.0.1:8090/api/collections/shop/records
```

Товар можна додати через адмін-панель: `Collections -> shop -> New record`. Заповніть `name`, `price`, `category`, `item`.

Покупку виконуйте через `ShopService.purchaseItem`. Не створюйте `purchases` вручну для реальної покупки, інакше баланс не буде списаний коректно.

### Перевірка покарання й амністії

```http
GET http://127.0.0.1:8090/api/collections/punishments/records
GET http://127.0.0.1:8090/api/collections/event_logs/records
GET http://127.0.0.1:8090/api/collections/users/records/<userId>
```

Для амністії викликайте `PunishmentService.useAmnestyPass`. Після успіху перевірте, що:

1. `amnestyPasses` зменшився на `1`;
2. запис покарання залишається незмінним;
3. у `event_logs` з'явився запис `amnesty_pass_used` із посиланням на покарання.

Спроба повторити дію має повернути помилку, не змінюючи баланс перепусток.

## 5. Автоматичні тести

Тести запуску:

```powershell
flutter test test\routine_service_test.dart
flutter test
```

Тестовий файл перевіряє старт серії, збільшення після попереднього дня та скидання після пропуску.

Для повного live-тесту з локальним PocketBase, тестовим акаунтом і тестовим товаром:

```powershell
flutter test test\live_integration_test.dart --dart-define=LIVE_PB_TESTS=true
```

Live-тест перевіряє успішну покупку, відмову при недостатньому балансі, списання amnesty pass, створення `event_logs` і блокування редагування покарання. Перед запуском має працювати PocketBase, а в `shop` має існувати товар з `item = integration-test-item` та ціною `25`.
